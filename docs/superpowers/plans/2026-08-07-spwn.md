# spwn Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a thin, easy-to-extend git wrapper called `spwn` that speaks friendly game-flavoured words while still accepting real git command words.

**Architecture:** A small Ruby CLI with a routing table inside the `spwn` script itself. Each command is a row that says which friendly names it accepts, which real git words it also accepts, what git command(s) to run, and whether it is a pass-through or a small convenience action. The script is intentionally thin: it does routing, friendly help, and one convenience action (`spwn save`); everything else is delegated to real git. Distribution is a `build/spwn.zip` plus a repo-based install helper, so both you and the child can install and update easily on Windows.

**Tech Stack:** Ruby, Bash for the zip/install helper where convenient, `build/spwn.zip` as the standalone artifact.

## Global Constraints

- `spwn` must be thin: no reimplementation of git, only routing and friendly wording.
- Command routing must be driven by a mapping table inside the `spwn` script itself.
- Adding a new alias must be a matter of adding a row, not editing control flow.
- Friendly words come first; real git words are also accepted where exposure is useful.
- No invented git verbs.
- First implementation should be thin: no extra confirmations beyond git’s normal behaviour, except where the script itself constructs the git invocation.
- Windows is the real target; install paths should be easy for a 12-year-old and for you.
- The README is the primary teaching surface and should stay in sync with the tool.

## File Structure

### Files created

- `bin/spwn` — main CLI entry point and routing table
- `bin/spwn-helpers.rb` — small helpers used by `bin/spwn`: friendly help text, routing lookup, git invocation wrapper, and the `spwn save` convenience action
- `bin/install-spwn` — repo-based install helper for the case where the child already has the course repo
- `build/spwn.zip` — standalone distribution artifact containing the same `bin/spwn` and `bin/spwn-helpers.rb` used by the repo path
- `docs/spwn-command-map.md` — human-readable map of the friendly words and the real git words they map to, used by the README and kept in sync with the routing table
- Updated: `README.md` — add a short “spwn” section that teaches the friendly words

### Files not created yet

- No gem, no package manifest, no separate project repo for now
- No fancy installer UI; “run this script” or “unzip this file and put it on your PATH” is enough

### Key interfaces

- `bin/spwn` is the public entry point.
- `bin/spwn-helpers.rb` exposes:
  - command routing lookup based on the first argument
  - a method to run a git command and forward stdout/stderr and exit status
  - a method that builds the `spwn save` sequence
  - a method that renders friendly help from the same routing table
- `docs/spwn-command-map.md` is derived from the same routing table so the README and the tool stay synchronized.

- [ ] **Step 1: Create `bin/spwn-helpers.rb` with the routing table and a tiny router**

Create `bin/spwn-helpers.rb` with enough structure to route commands by name and to tell whether a row is a pass-through or a convenience action.

```ruby
# bin/spwn-helpers.rb

COMMANDS = [
  {
    friendly: ["add"],
    git_words: ["add"],
    mode: :pass_through,
    description: "Stage files"
  },
  {
    friendly: ["save"],
    git_words: [],
    mode: :convenience,
    description: "Stage all changes and save them with a message"
  }
]

def find_command(entry_name)
  COMMANDS.find do |command|
    command[:friendly].include?(entry_name) || command[:git_words].include?(entry_name)
  end
end
```

This is only the shape for now. Do not implement full behaviour yet.

- [ ] **Step 1: Add the `spwn save` helper to `bin/spwn-helpers.rb`**

```ruby
def run_save(args)
  message = args.shift
  if message.nil? || message.empty?
    puts "spwn save: I need a message, like spwn save \"dragon moves\"."
    return false
  end

  run_git(["add", "-A"])
```

Add to `bin/spwn-helpers.rb`:

```ruby
def show_help
  puts "spwn - a friendly way to use git"
  puts
  puts "Commands:"
  COMMANDS.each do |command|
    names = command[:friendly].join(", ")
    real = command[:git_words].empty? ? "" : "(also: #{command[:git_words].join(', ')})"
    puts "  spwn #{names.ljust(14)} #{command[:description]} #{real}"
  end
  puts
  puts "Try spwn help for this message, or spwn <command> to learn more."
end
```

Create `bin/install-spwn` as a small script that installs the current `spwn` files for the current user.

For the first version, keep it honest and explicit:

```bash
#!/usr/bin/env bash

set -e

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
REPO_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"

if [ ! -f "$REPO_ROOT/bin/spwn" ]; then
  echo "spwn not found in this repository."
  exit 1
fi

# Prefer a user-local bin folder on Windows-style and Unix-style setups.
if [ -n "$LOCALAPPDATA" ]; then
  TARGET_DIR="$LOCALAPPDATA/spwn-bin"
else
  TARGET_DIR="$HOME/.local/bin"
fi

mkdir -p "$TARGET_DIR"
cp "$REPO_ROOT/bin/spwn" "$TARGET_DIR/spwn"
cp "$REPO_ROOT/bin/spwn-helpers.rb" "$TARGET_DIR/spwn-helpers.rb"
chmod +x "$TARGET_DIR/spwn"

echo "spwn installed to: $TARGET_DIR"
echo
echo "Next step: make sure $TARGET_DIR is on your PATH."
echo "On Windows, you can set this in System environment variables."
```
